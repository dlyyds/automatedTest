# 测试用例编写规则

本文档说明如何编写用例表格中的「测试步骤」「前置条件」「预期结果」等字段，使系统能够正确解析并下发远端命令。

> 用例上传后，可点击用例行的命令图标（`</>`）预览最终下发到板端的完整命令；也可点击「测试步骤」列标题旁的 `?` 查看内置规则说明。
>
> 系统不会把 sudo 密码显示在预览中，执行时自动注入。

---

## 1. 基本格式

### 1.1 步骤编号

每条步骤建议使用以下任一编号形式：

```text
1. 执行命令：ls -l /root/test
2. 执行命令：./run_test.sh --case 1
```

```text
1、执行命令：ls -l /root/test
2、执行命令：./run_test.sh --case 1
```

```text
1．执行命令：ls -l /root/test
2．执行命令：./run_test.sh --case 1
```

- 支持 `1.`、`1、`、`1．` 三种编号。
- 没有编号时，整段文本会被当作**一步**处理。
- 一个编号对应一条主命令。

### 1.2 一步中的多条命令

同一步内需要执行多条命令时，可以分行书写。以下形式的行会被拆成多条命令依次执行：

- `./...`
- `sudo ./...`
- `nvsipl_camera ...`
- `i2c...`（如 `i2ctransfer`、`i2cmastercmd`）
- `scp ...`
- `cat ...`
- `echo ...`
- `export ...`
- `source ...`

示例：

```text
1. 执行以下命令：
./run_test.sh --case 1
./run_test.sh --case 2
```

### 1.3 注释与标点

- 行内 `①②③` 注释以及 `注：` 之后的内容不会执行，可用于补充说明。
- 中英文冒号（`:` / `：`）都可以使用。
- 中文引号会自动转换为英文引号。
- 命令末尾的中文句号、逗号、分号等标点会被自动清理，但建议不要写在命令中。

## 2. 命令步骤怎么写

### 2.1 最稳妥的写法：加显式引导词

所有命令都建议加显式前缀，避免被当成说明文字跳过：

```text
1. 执行命令：ls -l /root/test
2. 起流：./nvsipl_camera -c /root/cfg.json -m "0x0001" -r 5
3. 测试指令：i2ctransfer -f -y 30 w2@0x36 0x30 0x1a
```

支持的前缀：

| 前缀 | 示例 |
| --- | --- |
| `执行命令：` | `执行命令：ls -l /root` |
| `需执行的命令：` | `需执行的命令：cat /proc/version` |
| `所执行命令：` | `所执行命令：mkdir -p /root/test` |
| `指令：` | `指令：sudo chmod +x /root/run.sh` |
| `起流：` | `起流：nvsipl_camera -c cfg.json -m "0x0001" -r 5` |
| `测试指令：` | `测试指令：i2cmastercmd -w 0x1a 0x10 0x01` |
| `命令：` | `命令：ls /root` |
| `输入命令：` | `输入命令：echo hello` |
| `故障注入：` | `故障注入：sudo ./fault.sh -i 7` |

### 2.2 不带前缀时可直接识别的形式

只有以下形式能在没有前缀时被直接识别为命令：

```text
1. ./run_test.sh --case 1
2. sudo ./run_test.sh --case 1
3. nvsipl_camera -c cfg.json -m "0x0001" -r 5
4. i2cmastercmd -w 0x1a 0x10 0x01
5. cd /root/test
6. scp /root/a.bin root@192.168.1.2:/tmp/
7. devopen /dev/video0
8. devclose /dev/video0
9. export CAM_ROTATE_CFG_PATH=/root/cfg.json
10. source /root/env.sh
11. `ls -l /root`
```

> **注意**
>
> 以下裸命令**不会**自动识别，需要加显式前缀：
>
> `ls`、`echo`、`cat`、`mkdir`、`sudo chmod`、`i2ctransfer` 等。
>
> 例如，下面两种写法只有第二种会执行：
>
> ```text
> 1. ls -l /root              ← 会被当作说明文字跳过
> 2. 执行命令：ls -l /root     ← 会执行
> ```
>
> 隐式写法要求命令中包含可执行关键字，否则会被当作说明文字。拿不准时，请加「执行命令：」前缀。

### 2.3 另一个终端执行

需要在另一个终端执行的命令，使用：

```text
1. 另一个终端执行：sudo ./fault_simulation_728.sh -i 7 -a 0x1a -n 5
```

- 建议使用**冒号形式**，不要用引号包裹命令。
- 使用引号（如 `另一个终端执行 'sudo ./a.sh -i 7'`）时，末尾引号可能被带入命令，导致下发命令多出一个 `'`。

### 2.4 shell 内置命令与持久化 Shell

`export VAR=value`、`source /path/env.sh` 会被识别为 shell 内置命令。

当用例中**同时存在**以下三类步骤时，系统自动启用「持久化 Shell」模式：

1. `export` / `source`
2. 重复步骤
3. 起流命令

持久化 Shell 模式下，环境变量在整个会话内有效；每条命令不是各自独立的 SSH exec，而是在同一个 shell 中执行。

## 3. 目录与前置条件

### 3.1 切换远端工作目录

```text
1. 进入测试目录
2. 进入目录 /opt/camera/test
3. cd /root/nvsipl_test
```

支持的关键词：

- 进入测试目录
- 进入调试目录
- 进入目录
- 进入工作目录

切换规则：

- 优先使用「工作区配置 → 默认远端路径」。
- 未配置默认路径时，取步骤文本中的绝对路径。
- 切换后，后续命令会以 `cd <目录> && <命令>` 的形式下发（持久化 Shell 模式除外）。

### 3.2 前置条件字段

前置条件与测试步骤分开填写，多条命令使用**英文分号 `;`** 分隔：

```text
echo ready; insmod /root/camera.ko; MANUAL_CONFIRM 确认板端已上电
```

规则：

- 前置命令按英文 `;` 拆分后**原样下发**，不经过测试步骤的命令解析。
- 中文分号 `；` 不作为分隔符，请使用英文 `;`。
- 任一条前置命令返回码非 0 时，该用例直接判 **Fail**，测试步骤不再执行。
- 工作区中关闭「执行前置条件」时，前置条件整体不执行。

### 3.3 人工确认

```text
MANUAL_CONFIRM 确认板端已上电
```

- `MANUAL_CONFIRM` 必须写在步骤或前置条件的**开头**。
- 执行到该步骤时，前端弹出「确认 Pass / 确认 Fail」对话框。
- 选择 Fail 时，该用例判 **Fail** 并停止后续步骤。

## 4. nvsipl 交互命令

```text
1. 执行命令：./nvsipl_camera -c cfg.json -m "0x0001" -r 5
2. 输入 gc 0
3. 输入 'ro'
4. 执行 dl 0, dl 2, el 3
5. 输入 q
```

### 4.1 支持的写法

- `输入 gc`
- `输入 gc 0`
- `输入 'ro'`
- `执行 dl 0, el 11`
- `发送 al`

### 4.2 支持的子命令

```text
gc  dl  dlo  el  elr  ro  al  ed  th  df  bp  sr  hs  ex  q
```

### 4.3 阻塞与非阻塞起流

- 起流命令带 `-r N`（N 秒后自动退出）时，属于**非阻塞起流**。后续交互输入会合并成管道命令一次下发，并在组间自动插入等待。
- 起流命令不带 `-r` 时，属于**阻塞型起流**，会占用 PTY，交互命令逐条发送，最后用 `q` 退出。
- 大写 `-R` 是功能参数，**不控制自动退出**，与是否阻塞无关。

### 4.4 自动注入 gc

如果步骤里没有显式的 `gc`，系统会根据起流命令中的 `-m` 掩码自动注入一条 gc 触发出帧。

### 4.5 执行模式

系统根据步骤内容自动选择执行模式：

| 模式 | 触发条件 |
| --- | --- |
| 顺序执行 | 普通命令，无特殊组合 |
| 持久化 Shell | 同时存在 `export`/`source`、重复步骤、起流命令 |
| 并行故障测试 | 阻塞型起流后还有后续步骤（如另一个终端注入故障） |
| PTY 单起流 | 只有一条阻塞型起流，无后续步骤 |

## 5. 重复与压力测试

```text
1. 执行命令：./nvsipl_camera -c cfg.json -m "0x0001" -r 5
2. 输入 dl 0, dl 2
3. 重复1-2
4. 重复步骤2
```

### 5.1 支持的重复写法

| 写法 | 含义 |
| --- | --- |
| `重复1-3` | 重复第 1 到第 3 步 |
| `重复1-3步骤` | 重复第 1 到第 3 步 |
| `重复第1~3步` | 重复第 1 到第 3 步 |
| `重复步骤1` | 重复第 1 步 |
| `反复起流10次` | 起流 → gc → 检测帧率 → q 退出，共 10 轮 |
| `重复起流5次` | 同上，共 5 轮 |

> **注意**
>
> 不要写成 `重复步骤1-3`。该写法会被解析为「重复第 1 步」，而不是第 1 到第 3 步。
>
> 正确写法是 `重复1-3`、`重复1-3步骤` 或 `重复第1~3步`。

### 5.2 重复指令何时生效

重复指令只有在以下模式中才会展开：

- **持久化 Shell 模式**（同时含 export、重复、起流）
- **并行故障模式**（阻塞型起流后还有步骤）

普通顺序执行中，重复指令会被忽略。

### 5.3 步骤序号

- 步骤序号从 1 开始，指**解析后的步骤顺序**。
- 建议重复范围只包含命令步骤，避免把说明、人工操作包含在内。

## 6. 人工操作与人工确认

```text
1. 手动切换 Camera 通道
2. 人为手动拔插 camera 线缆
3. MANUAL_CONFIRM 检查屏幕是否有显示异常
```

### 6.1 人工操作

包含以下关键词的步骤会被标记为人工操作，**不会自动下发**，仅在界面上提示操作人员：

```text
人为手动、手动切换、手动操作、手动拔、手动插、人工操作、
人工切换、人为操作、物理操作、拔插、插拔
```

### 6.2 人工确认

`MANUAL_CONFIRM` 写在步骤开头时，前端弹出「确认 Pass / 确认 Fail」：

- 选择 Pass：继续执行后续步骤。
- 选择 Fail：该用例判 **Fail**，停止后续步骤。

## 7. 会被跳过的内容与 NA

### 7.1 会被跳过的步骤

| 内容 | 说明 |
| --- | --- |
| `ssh ...` | SSH 连接由系统管理，步骤中的 ssh 命令会被跳过 |
| `注：` / `注意：` / `备注：` / `说明：` / `Note:` | 视为注释 |
| 以 `①` 开头的步骤 | 视为注释 |
| 纯英文说明 | 无中文、长度 ≥ 10 且没有可执行命令 |
| 描述性文字 | 含「查看 / 打开 / 确认 / 验证 / 检查」且不含命令 |
| 无法识别的步骤 | 标记为「未识别步骤（已跳过）」，不影响执行，但不会下发命令 |

无法识别的步骤可以点击行内的 **AI** 按钮解析后再预览。

### 7.2 NA 判定

用例任意字段出现以下内容时，整条用例自动标记为 **NA**，不会执行任何命令：

```text
待写入、方案待写入、验证方案待写入、待补充、待完善、
暂不测试、不适用、TBD、N/A、TODO、NA（单独出现）
```

## 8. 预期结果怎么写

在「预期结果」列用自然语言描述期望输出，系统自动提取匹配规则。

### 8.1 帧率检测

```text
30fps 正常出帧
```

- 从输出中匹配 `Frame rate (fps): 29.99` 格式的数据。
- 精确帧率容差为 **±20%**（如 30fps 对应 24–36fps）。
- 按 sensor 分别验证；如果命令带 `-m` 掩码，会优先校验掩码对应的 sensor。

```text
正常起流，帧率稳定
```

- 仅检查是否正常起流、帧率是否稳定，不做精确帧率比对。

```text
帧率在 25-30fps 之间
```

- 按范围校验。

### 8.2 文件生成检测

```text
生成 .yuv 文件
生成两个 .yuv 文件
生成 3 张 .raw 文件
```

- 支持的文件后缀：`.raw`、`.yuv`、`.png`、`.jpg`、`.jpeg`、`.log`、`.txt`、`.csv`。
- 数量支持阿拉伯数字和中文数字（两/三/四/五/六/七/八/九/十）。
- 实际文件数 **≥** 预期数量即通过。
- 文件搜索目录：优先使用「image_storage_path」配置（如已启用），否则使用默认远端路径；搜索最近 3 分钟内生成的文件。

### 8.3 关键字匹配

```text
日志中包含"streaming"和"initialized"
无报错，正常退出
寄存器值为 0x1A3F
```

- 引号内的文本会被精确匹配。
- 英文技术关键字会自动提取（≥ 4 个字符）。
- 十六进制值（如 `0x1A3F`）会作为关键字匹配。
- 所有关键字的匹配率 **≥ 80%** 时通过。
- 含「无报错 / 无异常 / 无错误 / 不报错 / no error」时，会检查退出码。

### 8.4 故障测试

```text
查看到 IMX728_CLKMON_ERROR 故障报出
注入故障后 DTC 上报数据为 0x00 0x01 ...
```

- 预期结果涉及 `*_ERROR`、`*_FAULT`、故障注入、DTC 上报时，输出中的 ERROR 属于**正常预期行为**，不会被当作失败依据。

### 8.5 帧同步检测

```text
帧同步误差小于5ms
```

- 当执行命令含 `--showmetadata` 参数时，自动进入帧同步检测模式。
- 解析各 Camera 的 TSC SOF 时间戳，按时间片分组计算最大差值，与阈值比较。

### 8.6 其他模式

| 模式 | 触发条件 | 结果 |
| --- | --- | --- |
| DL/EL 阶段检测 | 输出含 Disable Link / Enable Link | 按阶段分析各传感器状态变化 |
| 嵌入行信息（metadata） | 预期含曝光/增益/帧序号，输出含 Camera ID/Frame Counter | 自动截取 metadata，标记为 **Review** 待人工核对 |
| SR/HS 用例 | 预期含 ROI/直方图，输出含相关特征 | 标记为 **Review** 待人工核对 |

## 9. 判定状态

| 状态 | 含义 | 触发条件 |
| --- | --- | --- |
| Pass | 通过 | 关键字匹配率 ≥ 80%，且无严重错误 |
| Fail | 失败 | 匹配率 < 80%、致命错误、执行超时、人工确认失败、前置条件失败 |
| Review | 待确认 | metadata / SR/HS 用例需人工核对；或仅退出码异常但无其他失败证据 |
| NA | 不适用 | 用例内容包含待写入 / 待补充 / TBD / N/A 等 |
| NT | 未测试 | 尚未执行 |

启用 AI 判定后，判定优先级为：

1. **AI 判定优先**（工作区配置为「始终使用 AI」时）。
2. AI 仅在规则判定为 **uncertain** 时介入（配置为「仅不确定时」）。
3. 关闭 AI 时，使用规则判定。

---

## 10. AI 兜底解析

- 只有在规则解析出现「未识别步骤」时，AI 才会参与。
- AI **不会改写**已被规则识别的步骤。
- 点击「测试步骤」列内的 **AI** 按钮可单条解析，或使用工具栏的批量解析。
- 置信度 **≥ 0.6** 的 AI 结果才会替换未识别步骤；低于 0.6 仅作为建议显示。
- 解析结果会缓存在当前会话中，执行和「查看执行命令」都会复用。

## 12. 常见问题

### Q1：命令没有被执行？

先点击该行的命令预览按钮，确认步骤是否被识别：

- 如果显示「未识别步骤」，改用 `执行命令：<命令>` 的显式写法。
- 也可以点击 **AI** 按钮进行兜底解析。

### Q2：`-r` 和 `-R` 有什么区别？

- 小写 `-r N`：运行 N 秒后自动退出，属于非阻塞起流。
- 大写 `-R`：功能参数，不控制退出。

需要与脚本/人工交互的用例，应使用**不带 `-r`** 的阻塞模式。

### Q3：多条命令能写在同一行吗？

可以用 `;` 连接，但会被当作一条 shell 命令行执行，出错时难以定位。建议拆成多个编号步骤。

### Q4：前置条件为什么不执行？

检查：

1. 是否使用**英文分号 `;`** 分隔多条命令。
2. 工作区是否开启「执行前置条件」。
3. 前置命令是否返回非 0 退出码（会导致用例直接 Fail）。

### Q5：为什么重复没有生效？

重复指令只有在以下模式中生效：

- 持久化 Shell 模式（同时含 export、重复、起流）
- 并行故障模式（阻塞型起流后还有步骤）

普通顺序执行中，重复会被忽略。

### Q6：NA 用例为什么没有执行？

用例任意字段包含 `待写入`、`待补充`、`待完善`、`暂不测试`、`不适用`、`TBD`、`N/A`、`TODO` 或单独的 `NA` 时，整条用例自动判为 NA。

### Q7：sudo 命令的密码在哪里配置？

在工作区配置中设置 sudo 密码。执行时自动注入；命令预览中不会显示密码。

### Q8：如何确认最终下发到板端的命令？

- 在用例列表中点击该行的命令图标，可预览单条用例。
- 勾选用例后点击工具栏的「查看执行命令」，可批量预览。
- 预览会显示执行模式、前置条件、每条实际命令、人工操作/确认步骤、未识别步骤等。
